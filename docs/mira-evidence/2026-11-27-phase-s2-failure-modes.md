# Mira Phase S2 failure modes

Recorded before implementation on 2026-11-27. The scope is the native app and its TesterArmy checks. The saved-file and generation API contracts stay the same.

| Area | Failure | Check and expected result |
| --- | --- | --- |
| Reel progress | An unapproved Reel appears ready, or a completed Reel skips approval after undo. Missing or stale shots get the wrong next step. | Run B1–B3. Verify the shot list, filming, Done and Continue honor approval. Check that a fresh project moves from idea to script to shots. Keep existing filmed progress when approval changes. |
| AI request | A refused request looks active. Retry creates a new job or uses new input. Stop on an unknown job leaves it active. A late reply applies after Stop or an edit. | Run B4–B5 with sample data. Check the same job ID and input across retries in source and verify waiting, automatic restart and Stop in the app. Check input revision and identity before applying a reply. Verify a saved active request can reconnect on relaunch. |
| Today card | A retry erases the earlier idea. A card with missing or out-of-date output can open Your words. The pager jumps again when a second card completes. | See a failed card and retry it. Check that a ready card opens the matching words and that the first ready card wins the first automatic jump. Review the earlier-output and brief-revision paths. |
| Your words | Approval starts filming before shots match the script. The shot update starts or opens filming twice. A failed update hides Retry. Clearing or editing a proposal erases saved words. | Revise the words, use the proposal and approve. Observe the shot-update state, then check that one filming plan opens with matching words. Check the rejected, stopped, stale and reconnect paths. |
| Where am I | The two tab histories interfere. Back, project sections or a relaunch reopen the wrong screen or bypass approval. An older file loses its last screen or shot. | Switch tabs and use Back. Relaunch on Today cards, Your words, the Projects filming plan and filming. Run B2 with removed approval. Check the legacy navigation fallback and the unchanged Codable declarations. |
| Tab bar | The last line or control stays behind the floating bar on a long page or on a vertically scrolling Today card. | Scroll the main long pages and the card to their ends on the iPhone. Check the bottom control or line against the bar and capture the screen. Include Shot 1 on the filming plan. |
| Microphone and permissions | The note uses terms a new user cannot follow or implies that the phone sends audio. | Check the note on Plan step by step and inspect the other microphone and permission text. Keep the consent choices and scope of data sharing. |
| Data on the phone | Install or sample launch removes Instagram login or AI permission, writes fixture data to the live library, or resets saved work. | Capture Profile before install, after an in-place install, and after testing. Stop at any loss. Check fixture repository isolation in source. |
| Live request budget | A retry or a separate scenario exceeds 12 requests. | Record each live operation before asking the app to start it. Count a Today batch as three. Check the ledger before reruns. |
