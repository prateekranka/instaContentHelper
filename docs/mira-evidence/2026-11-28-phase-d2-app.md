# Mira Phase D2 app evidence

Branch `claude/mira-d2-app` started at `b1dc55c`. The [failure modes](2026-11-28-phase-d2-app-failure-modes.md) were committed before the code. Times below use IST on 2026-11-28 unless marked UTC.

## App changes

- Today reads the step for each card from the job. A card with no step keeps the simple D1 wait. The wait shows an estimate of about one minute. The first idea gives one success haptic. A card opens as soon as its text is valid and successful.
- Once a Today card succeeds, its picture status requests send `pictures: true`. Pictures appear on the matching shots in Today, the filming plan and filming. While a picture is pending, failed or missing, Mira shows the drawn frame. If an image URL fails, Mira asks for a fresh URL with status. This path uses the original job ID.
- The saved project has one additional optional field, `shotPictureSources`. It maps storyboard IDs to the original Today job ID and maps the current shot IDs to that job's shot IDs. Earlier projects load with no field. The earlier app ignores the extra JSON key. The file version stays the same. Mira keeps picture URLs and image data out of saved projects.

### AI request machine

| State | Events and result | Next action |
| --- | --- | --- |
| Idle | Initialise from the saved job | None |
| Waiting to start | `send` retries a refused start | Stop (`stop`) |
| Sending | `accepted` records the active job. `refused` waits. `saveFailed` or `reconnect` keeps the job for recovery. | Stop (`stop`) |
| Working | `progress` replaces the step for the same job. `received` applies the terminal result or requests reconnect. | Stop (`stop`) |
| Waiting to retry | `progress` follows server backoff and a new claim. `received` applies a result. | Stop (`stop`) |
| Stopping | `received` applies the cancel outcome. `reconnect` preserves an unconfirmed cancellation. | Wait (`wait`) |
| Needs reconnect | `send` reconciles the same job ID. | Reconnect (`reconnect`) |
| Failed or stopped | A new retry uses the current input. | Try again (`retry`) |
| Done | `picturesReceived` records each shot's pending, ready or failed status. `pictureLoadFailed` moves a matching ready URL to refresh or fallback. | None |

### Today card machine

`workChanged` projects the current request, any previous text and the current brief revision. `make` accepts a ready card. `retry` accepts failed, ready or out-of-date cards.

| State | Data and event | Next action |
| --- | --- | --- |
| Waiting | `workChanged` reports a refused start. | Stop (`stop`) |
| Making | `workChanged` reports sending, working or stopping. A working request can carry a server step. | Wait (`wait`) |
| Waiting to retry | `workChanged` reports server backoff. | Stop (`stop`) |
| Reconnect | `workChanged` carries a recovery message. | Reconnect (`reconnect`) |
| Failed | `workChanged` reports failure or cancellation. `retry` is allowed. | Try again (`retry`) |
| Ready | `workChanged` carries valid text and per-shot picture states. `make` and `retry` are allowed. | Make this one (`makeCard`) |
| Needs update | `workChanged` detects that the brief changed. `retry` is allowed. | Update this idea (`updateIdea`) |

The S1 TLA+ models check approval gates, real working requests, stop, the next words action and the text slot limit. D2 changes the display and picture polling after terminal success. The checked rules are unchanged, so the models did not require a TLC run.

## Reproduce on the phone

The worktree-local runner `work/run-d2app-phone.sh` uses the existing signed driver profile from `work/keep/pr37-phone-3.env`. It waits up to 15 minutes for the device claim. It uses one worker and no automatic retries. The Keep configuration is rooted at `work/` so TesterArmy accepts the evidence directory. The Keep test uses a normal launch. Sample tests use `MIRA_E2E_FIXTURE_SESSION=mira-d2app-phone` and `-MCO_APPEARANCE light`.

For D2 sample cases, run `node tests/fixtures/mira-d2-server.mjs`. Set `MIRA_E2E_D2_ENDPOINT` to the phone-reachable HTTPS address of the fixture and `MIRA_D2_FIXTURE_CONTROL` to its control origin on the Mac. The fixture uses port 18796 by default. It receives text start and status requests from the app. E2E controls when the server returns each step and picture state. Its image endpoint rejects the first URL with HTTP 403 and serves the fixture image at the replacement URL.

```sh
python3 work/d2app-build.py device > work/build-device-d2app.log 2>&1
python3 work/d2app-build.py sim > work/build-sim-d2app.log 2>&1
nohup caffeinate -i work/d2app-keep-install.sh
nohup caffeinate -i work/d2app-sample.sh
nohup caffeinate -i work/d2app-rebuild-verify.sh
nohup caffeinate -i work/run-d2app-phone.sh live live --grep '^(1 Today brings back|5 Projects Plan step)'
nohup caffeinate -i work/d2app-transport-verify.sh
nohup caffeinate -i work/run-d2app-phone.sh keep-after-tests keep
python3 scripts/check-agent-rules.py
```

The live ledger sits in `work/evidence/d2app/live-ledger`, outside TesterArmy's output directory. Keep the existing ledger for any approved test-only retry. Sample scenarios use fixture text and pictures. The separate consent cases read the real saved decision or a non-writing Debug override.
