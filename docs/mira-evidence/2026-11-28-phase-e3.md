## App behavior

- Deals accepts shared text and readable PDF text. The Share Extension writes one protected file per share to the App Group. Mira loads the oldest waiting brief when the creator opens or returns to the app. If there is already a nonempty draft, Mira keeps it and shows that another brief is waiting. Mira moves a shared file to the imported folder after saving its text.
- The extension tells the creator to open Mira. The app then selects Deals and shows **Read this brief**. The iOS Share Extension point has no supported way to open the containing app. Notes must send a copy that contains text. A scanned PDF without selectable text uses the paste path. [Apple extension API](https://developer.apple.com/documentation/foundation/nsextensioncontext/open%28_%3Acompletionhandler%3A%29?language=objc)
- **Paste a brief** opens an editable text box and a system Paste button. Mira requires current AI permission before a new live read. A reconnect checks the saved job first and uses the same ID and input if it needs to submit again.
- Mira presents the source brand, fee, deadline clause, disclosures and codes. It shows the checklist with excerpts and the items to check with the brand. **Looks right** saves the card. The tracker keeps dates for Posted, Brand told, Confirmed and Paid.
- Home shows confirmed, unpaid deals with the fee, deadline and an action that opens the exact card. Deals also keeps paid cards. `MiraStore.activeDealChecklist` supplies the newest unpaid deal's reviewed checklist when it has items. The E2 merge must connect that value to `pickIdea`.

## State machines

### Brief reading

| State | Events | Next action |
| --- | --- | --- |
| Empty | Begin from Deals or a shared brief | Paste a brief |
| Editing | Edit, import into a blank draft, or read valid text | Read this brief |
| Reading | Receive a matching result or record an interruption | Wait |
| Reconnect | Resume the saved request | Reconnect |
| Failed | Edit or read again with a new request | Try again |
| Reviewing | Edit the source or confirm the proposed card | Looks right |

### Deal card

| State | Events | Next action |
| --- | --- | --- |
| Reviewing | Confirm the source and proposed terms | Looks right |
| Saved | Apply a valid tracker event | Open deal |

### Deal tracker

| State | Events | Next action |
| --- | --- | --- |
| To post | Record the Posted date | Mark as posted |
| To tell the brand | Record the Brand told date | Mark brand told |
| To confirm | Record the Confirmed date | Mark as confirmed |
| To pay | Record the Paid date | Mark as paid |
| Paid | — | — |

The Home feed adds a deals-only state. Its continuing state can show deals and unfinished Reels in the same feed. [Complete state tables](../state-machines.md)

## Saved fields

Mira still uses the version 2 document. E3 adds two optional top-level fields.

| Field | New data |
| --- | --- |
| `deals` | Reviewed deal ID, source text, terms and review date. Terms contain `brand`, `fee`, `deadline`, `deadlineExcerpt`, `checklist`, `disclosures`, `codes` and `unresolved`. Each checklist item contains `id`, `kind`, `text`, `excerpt` and optional `requiredText`. Tracker dates are optional `postedAt`, `brandToldAt`, `confirmedAt` and `paidAt`. |
| `dealBriefDraft` | Draft `id` and `text`. It can hold a matching `job` with its ID, exact input and optional creator ID, the proposed `terms`, or an `issue` message. A confirmed deal replaces this review state in the same document save. |

Earlier documents can omit both keys. The earlier decoder ignores these keys when opening a new document. If the old app saves the file again, its encoder will omit these new keys. This compatibility check used source. A phone downgrade is not run (phone blocked).
