### Model changes (match the code)

- MiraReel has five switches, one for each fix: `ProjectsPathGuarded` (B1), `ShootingScreenGuarded` (B2), `StageHasApproval` (B3), `RefusedShownAsWaiting` (B4), `StopUnknownStops` (B5). All are TRUE in MiraReel.cfg.
- New: a `waiting` job state (refused start), `SendAgain` (the same job is accepted later), `ShotListApprove` (the shot list opens Your words), Stop on a job that the server does not know → `cancelled`, the filming gate on tab return and on relaunch → Your words, the "approving" stage.
- MiraTodayLimit: `Request` sends at once if the server has room, else the card is `waiting` (AppQueuesWhenFull = TRUE). `SendWaiting` sends it when a place is free.
- Abstractions: the filming gate is modeled as Your words (its only button goes there). The 30-send limit of the backup is not in the model. The short time while a start is in flight (the card shows "Mira is making it") is not in the model.

## Independent review (before the e2e)

A separate reviewer read the diff with no knowledge of how it was written. It found 4 problems. All 4 were confirmed in the code and fixed in the second code commit:

1. A waiting idea could stay "Waiting to start…" for ever if a send failed for another reason (no network, save failure). Now a failed send clears the waiting mark, so the error and Reconnect show; a save failure keeps the backup timer going.
2. B3.4 was not done: Continue opened the ideas screen, not Your words, after she went Back. Now `todayResumePath` and `resumePath` open Your words for the "Words to approve" stage.
3. The B4 scenario had a timing problem (the ideas pager jumps to the first ready idea). The scenario now waits for all ideas before it opens idea 3.
4. "See today's ideas" could open Your words. It now always opens the ideas screen.

The reviewer also checked and found no problem in: the approval gate on all paths to "Mark filmed", the new stage in every switch and label, B5 (only `not_found` means stopped; the words stay), and the B1, B2 and B5 scenarios.
