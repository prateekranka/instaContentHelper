## App behavior and saved data

- The approved shot list and the existing Finish action open Add your clips. PhotosPicker supplies videos in pick order. Mira matches them by duration, with recording time when available and pick order for ties and extra candidates. The creator sees the matched clip name and duration for each shot. She can change a match or exchange clips between two shots. Home reopens unfinished delivery.
- AVFoundation cuts from the start of each matched clip, in shot order. It scales and center-crops to 1080 × 1920 at 30 frames per second and keeps available source audio. It renders the hook during the first three seconds and the planned text during each shot. A clip up to 0.05 seconds shorter than planned uses its available duration. Shorter clips must be replaced. The finished Reel opens full screen. Save to Photos requests add-only access when tapped. [Apple video composition documentation](https://developer.apple.com/documentation/avfoundation/avmutablevideocomposition)
- For a linked deal, `briefCheck` receives the reviewed checklist and text from the current export, caption and script. Its shot descriptions come from the plan. The review shows Met, Missing and Can fix. Caption fixes append approved text. On-screen fixes save a new export before marking the item Met. Mira uses the existing AI permission and paired-account transport. A reconnect checks the same saved request ID.
- Share to Instagram copies the caption and passes the local video to the iOS share sheet. If Instagram does not appear there, the creator can save to Photos and select the video in Instagram. After an explicit confirmation, Mira records Posted. The read-only insights response supplies no new media ID, post timestamp or permalink. The verified You're live state has no production caller with the current API.
- `brandNote` receives the brand name, confirmed posted status and verified caption and on-screen checklist items. The creator enters the brand’s WhatsApp number with country code. Mira opens a draft with that number and prefilled text. The draft and tracker stay pending until the creator confirms she sent it. E3’s manual tracker actions remain available in Deals.

The document remains version 2. The only added top-level project keys are optional `dealID` and `delivery`. The nested delivery record contains `clips`, `plans`, `briefReview`, `caption`, `sharedAt`, `sharedExportID`, `post` and `brandNote`. Each plan stores assignments by shot ID, approved extra text and the latest export for that shot-list revision. The clip records store only file identity, picker identity when provided, name, duration, creation time when available, and byte count. The export record stores file identity, the render recipe and byte count. The brief and note records keep job IDs, request inputs and results or errors. The post and note records keep the creator’s confirmation dates. The WhatsApp phone number stays in the screen during entry. Source inspection confirms earlier decoders ignore the new project keys and older files can omit them. Saving again in an earlier app can drop unknown keys.

Clips and MP4 exports occupy separate files in `Application Support/Mira/Media/`. The Debug fixture uses a separate fixture library. No video or photo bytes are sent to AI. Photos originals stay in Photos. Mira retains original copies and completed exports, including superseded exports. Storage grows by each copied clip’s file size and each completed MP4, plus a temporary import copy during selection. The export size varies with duration and content. The three synthetic inputs total **110,898 bytes** as measured from their files. Real clip storage and export size remain **not run (phone blocked)**.
