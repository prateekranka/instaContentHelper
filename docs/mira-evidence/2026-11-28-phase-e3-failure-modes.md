# Mira Phase E3 failure modes

| Area | What can break | Verification |
| --- | --- | --- |
| Share and PDF | A host sends text in an attachment or a PDF file URL. A second share overwrites the first. A scanned PDF has no text. The app reads a partial file or replaces an open draft. | Share a Notes copy with the phone driver. Open Mira and check the exact text in Deals. Repeat with two briefs and a text PDF. Check that a scanned PDF explains how to use paste. Inspect activation rules, the atomic App Group write and extension embedding. |
| Paste and draft | Empty or oversized text starts a request. Pasting the fixture changes currency or line breaks. Returning from another tab loses the brief. | Paste into the Deals form. Check empty input and a long input before sending. Leave and reopen Deals to check the text. |
| Consent and recovery | A share starts AI without a tap or consent. Lost network or relaunch creates a new request. A reply from a different request or account changes the card. | Check that shared text waits for Read this brief. Use a fixture that interrupts a request and resumes the same job. Inspect the consent and account gates and the request identity match. Keep the real AI decision unchanged. |
| Review | A fee, date, disclosure, code or checklist term is altered. Missing details vanish. The proposal appears as a saved deal before Looks right. | Use the six-item sample with an unresolved link. Check literal terms and source excerpts. Check Home before and after confirmation, then reopen the saved deal after relaunch. |
| Tracker | Repeated or out-of-order taps skip a step, change an earlier date, or lose dates on reopen. | Check each next action and date from Posted through Paid. Relaunch before and after payment. Check that a paid deal remains in Deals. |
| Home and E2 | Home shows an unreviewed or paid deal. The card opens the wrong detail. E2 gets an empty, stale or unreviewed checklist. | Check Home fee and deadline and open the matching card. Check Home again after payment. After the E2 merge, run one live pick within the cap and check its use of the reviewed deal. |
| Existing library and account | The new fields break older JSON or the new build loses projects, filming, account access or consent. | Check both document shapes in source. Run the earlier sample scenarios and the three read-only Keep checks on the phone. |
| Integration | A new state has no documented transition, the extension fails to sign, or CI rejects a Swift expression. | Run agent rules and proof, check state documentation, run the shared TLA+ suite and build both generic destinations. Check the embedded extension signature and required Info.plist keys without printing values. Claude checks Xcode 26.3 CI. |

Phone and live checks are not run (phone blocked). The morning live run has a cap of three `dealBrief` jobs and two `pickIdea` jobs. Start with one request for each operation. Retry a scenario at most once and only after a test fix.
