## App and response changes

- **How you're doing** shows actual followers, reach and saves. It uses the current snapshot and the existing weekly baseline in order. With a legacy response, it uses the supplied current counts and formatted changes. It does not derive an earlier count from a rounded change. Missing counts or comparisons show **Not enough data yet**.
- **Mira noticed** uses the existing `dailyNote` operation. It starts only after current AI permission. With the separate E2 Instagram choice, it includes up to two real snapshots, oldest first. Without that choice, snapshots are empty and the note gets open Reels, open deals and the language. Same-day Home reentry uses the in-memory result. A cold launch can send a start to find the server's same-day result. It polls the admitted job ID. The current permission can hide a cached note that used Instagram. The app checks that each suggested Reel or deal is still open before it shows or handles its action. A note with `none` has no button.
- **What worked** shows up to five returned captions and their available counts. It ranks the posts returned by the existing recent-media read by saves, then likes, then comments. **Make one like this** starts the existing Home pick with the selected caption excerpt as its pattern after the E2 Instagram choice allows it. **Show another idea** can use that pattern again. The existing pick review creates a Reel only if the creator accepts it. [Meta Instagram Media fields](https://developers.facebook.com/docs/instagram-platform/reference/instagram-media/v21.0/)
- The Instagram Insights response source adds optional `snapshots`, with optional counts and `topPosts` in the latest snapshot. The media request uses the existing Instagram connection and saves read. A rejected expanded request can fall back to the earlier saves query. The current deployed response shape has no top posts. Live What worked needs the additive response to be deployed separately. This work used the existing daily-note server contract and made no deployment or settings change. [Phase E server contract](2026-11-28-phase-e-server.md)
- **E5 adds no saved fields.** The two Home machines and the selected pattern in pick context stay in memory. Accepted picks use the existing request, idea, script and storyboard fields.

## State machines

### Home insights

| State | Event and result | Next step |
| --- | --- | --- |
| `unopened` | `load` starts an account-scoped read. `reset` keeps the initial state. | — |
| `loading` | A matching `received` uses the report or records unavailable. A new `load` replaces the attempt. `reset` clears the state. | Wait |
| `unavailable` | `load` starts another read on Home reentry. `reset` clears the state. | — |
| `ready` | `load` starts a new read. `reset` clears the state. | Make one like this for each eligible post |

### Daily note

| State | Event and result | Next step |
| --- | --- | --- |
| `idle` | `start` begins the current account and UTC day's note. `reset` keeps the initial state. | — |
| `loading` | `received` records a valid note for the current attempt. `failed` records the failure for that attempt. `start` allows a different scope. `reset` clears the state. | Wait |
| `ready` | `start` allows a different scope. `reset` clears the state. | One action when available. Make an idea, continue the exact Reel or open the exact deal. |
| `unavailable` | `start` allows a different scope. `reset` clears the state. | — |
