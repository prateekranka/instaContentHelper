# Mira Phase E5 failure modes

Recorded before implementation on 2026-11-28. The phone needs Bobby’s passcode for XCTest. The phone and live scenarios are planned checks.

| Area | Failure mode | Verification |
| --- | --- | --- |
| How you're doing | A missing period becomes zero, a rounded change is reversed into a false baseline, or a partial response hides a real count. | Open Home using known snapshots. Check the three labels, an increase, a decrease, a zero count and a missing count or baseline. Check the legacy response and the disconnected state. |
| Mira noticed input | Home sends Instagram data without the E2 choice or sends any AI request without current AI permission. | Inspect the fixture request with Instagram results allowed and denied. Check that denial omits all snapshots and keeps the open work. In a non-writing general consent override, confirm Home makes no note request. |
| Daily reuse | Tab reentry issues another start, a cold launch creates a second paid job, or polling uses the new request ID instead of the returned ID. | Count starts, status IDs and new jobs in the fixture. Revisit Home on the same day, then relaunch and receive the original job using a different request ID. |
| Scope and recovery | A late reply appears after an account change, a previous UTC day remains visible, or a cached note displays Instagram data after permission changes. A failed request traps Home. | Return an old cached note to a no-permission launch. Confirm its text and action are absent. Return a failed job and confirm Home still opens and does not start a new job on tab reentry. Check the account, permission and day guards in source. |
| Daily actions | A note shows multiple actions, opens the wrong Reel or deal, or offers an action for finished work. | Exercise all four action types with exact locators. Mark the target deal paid and return to Home. Check the same note has no deal button. |
| What worked | An invented or missing count appears, the card sends the wrong caption, or the chosen task cannot use its pattern after generating another pick. | Show fixture cards with distinct captions and counts. Tap one card and inspect the exact pick input, the resulting Home pick and its next action. Check permission gating and the no-post state. |
| Saved work and earlier flows | Opening Home changes the document format, or insight actions bypass the existing review flow. | Compare saved declarations against the base. Prepare the earlier sample suite and include its approval, consent, undo, tab and recovery scenarios. Run the in-place Keep checks before and after installation and after testing once the phone is available. |
| Live cost and settings | A Keep or sample launch generates a paid note or a live action exceeds the morning cap. Build logs expose runtime settings. | Disable the daily note on non-E5 live test launches. Reserve live submissions in the existing ledger. Limit E5 to two daily-note opens with one reused and two picks. Build for generic iOS and generic Simulator. Record required Info.plist keys as yes or no. |
