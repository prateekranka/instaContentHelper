# Mira Phase D2 app failure modes

| Area | What can break | Verification |
| --- | --- | --- |
| Today wait | The app shows completed work before a server step arrives, reverses steps across parallel cards, or repeats the idea haptic. Cards wait for all text jobs. | On the phone, drive a fixture through idea, script, storyboard and terminal success at separate times. Check the visible order and that a usable card opens while other jobs or pictures are pending. Check that the first idea provides one haptic event in source. |
| Legacy and interrupted jobs | A response without `step` fails decoding or shows invented progress. A delayed response can repopulate a stopped or replaced batch. | Run the legacy fixture and check the simple wait screen. Run the existing Stop and rate-limit cases with sample data. Inspect the job and batch identity checks. |
| Shot pictures | A status poll omits opt-in, matches a picture to the wrong shot, blocks card selection, or never shows the drawn frame when pending, failed or missing. | Use staggered fixture results. Check drawn previews first, then the matching ready picture and failed fallback. Open the plan and individual shot while previews can still change. |
| Signed URLs | A failed or expired image stays broken, causes a second AI start, or leaks its signed URL into saved files or evidence. | Have the fixture reject an image request and issue a fresh URL on status. Check that the image appears and that the fixture records no new start. Review persistence and evidence for signed URLs. |
| Saved projects | Earlier documents fail to load, changed shots show an older picture, or the new build loses filming progress or backup recovery. | Run the existing reopen and recovery journeys. Check that the saved format remains compatible and that picture lookup follows the source storyboard and shot. |
| Brand brief | An edit leaves the previous confirmation active or an unchanged save revokes it. | Run the S3 confirmation case on Bobby’s phone and check that edited terms require confirmation again. |
| Speech denied | A system interruption hides the app. The app prompts again or blocks typing. | Keep the existing denied permission. Tap the mic, activate Mira again if needed, verify one Open Settings action, then type in the same flow. |
| Live step-by-step | A transport interruption stops the plan before the shot list or a recovery starts a duplicate request. | Run the live scenario once within the text budget. Record the visible result, time, and generation actions. |
| Privacy and install | Installing removes the Instagram session or the existing AI decision. | Run the Profile Keep check before and after install and after testing. Stop on a change. Install over the existing app. |
| Live cost | The phone test starts more than six text requests or eighteen picture requests. | Reserve three text requests for Today and three for step-by-step. Count Today shot slots and request actions. Separate observed pictures from provider usage. |
| Build and rules | Simulator and device builds diverge, runtime settings are missing, or the new state introduces a second mutable owner. | Build both targets, check required device bundle settings as yes or no, and run all seven agent-rule groups. |
