## State machines

### Reel progress

| State | Event and result | Next action |
| --- | --- | --- |
| Choosing | Saved work has no selected idea | Choose an idea |
| Writing | The selected idea has no script | Write your script |
| Planning | The shot list is absent or out of date | Make or update the shot list |
| Approving | The shot list is current and the current words need approval | Approve your words |
| Ready | Words and shots are current and filming has yet to start | Start filming |
| Filming | Filming has started and a shot still needs work | Continue filming |
| Complete | Every shot is filmed and no shot needs review | Review your filming plan |

`workChanged` derives progress from the project record. Removing approval or changing shots can move progress back to an earlier stage.

### AI request

| State | Events and result | Next action |
| --- | --- | --- |
| Idle | A new saved job becomes eligible to send | — |
| Sending | Accept to work, refuse to wait, or require reconnect after an error | Stop |
| Waiting to start | Send again with the same job or stop | Stop |
| Working | Receive a result, ask to reconnect, or stop | Stop |
| Stopping | Receive the stop result, treat an unknown job as stopped, or ask to reconnect after another error | Wait |
| Needs reconnect | Send the saved job again or stop | Reconnect |
| Failed | Start a new request | Try again |
| Stopped | Start a new request | Try again |
| Done | The caller can review or apply the result | — |

The generation task handles transport. The phase enum controls the screen. Error messages are associated text. The saved job ID, input and input revision still gate replies and proposal application.

### Today card

| State | Events and result | Next action |
| --- | --- | --- |
| Waiting | A refused request can resume or stop | Stop |
| Making | The current request progresses | Wait |
| Reconnect | Check the same saved job | Reconnect |
| Failed or stopped | Retry can keep an earlier output visible | Try again |
| Ready | Make from a full result for the current brief, or request a revision | Make this one |
| Needs update | Retry with the current brief | Update this idea |

`workChanged` projects the saved output and request phase. `make` and `retry` check the state before the store acts.

### Your words

| State | Events and result | Next action |
| --- | --- | --- |
| Reviewing | Approve the words or ask for a change | Approve your words |
| Changing | Edit the note, send it, or cancel it | Send |
| Waiting or writing | The request can stop | Stop |
| Needs reconnect | Check or stop the saved job | Check again |
| Stopping | Wait for the stop result | Wait |
| Proposal | Apply the new words or keep the existing words | Use this |
| Retry | Start a fresh revision or keep the existing words | Try again |
| Needs shots or update failed | Retry the shot update | Try again |
| Applying shots | Apply the matching result or record a failed application | Wait |
| Ready | Open filming | Start filming |
| Opening | Wait for navigation to finish | Wait |

The view sends events. The store approves the words, requests updated shots when necessary, applies a valid matching reply, and opens filming once. A stale proposal stays saved for review.

### Location

| State | Events and result |
| --- | --- |
| Today or Projects | Select tab, replace a tab's path, open a project, push a screen, go to Your words, remember a section, or remove a deleted project from history |
| Editor, Today cards, Your words, filming, Done | Each typed destination maps to its existing saved route and project screen |

`MiraStore.location` owns both tab histories and remembered project sections. SwiftUI binds to paths derived from it. Load uses the existing `restoredNavigation()` check and the saved `position` and `lastScreen` fields. Save derives those same keys from the location and the current shot index. The three saved Codable records retain their fields and raw values. The store uses the same location to choose which Reel to Continue.
